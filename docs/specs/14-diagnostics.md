# TreeDumper, debug screen and selector-health alerts

**Purpose.** Give the implementer reproducible selector evidence and tell the user when a target app's visible hierarchy has become unrecognizable. Health detection operates on structured reasons. Only explicit debug capture writes a tree.

| Component / method | Dependencies and behavior |
|---|---|
| HealthMonitor.record(package, version, classification, sample) | Run on the serialized service pipeline. Count only complete readable frames for the verified foreground target. Keep per-package/version streak start, last sample and count. Count at most one sample per second. Clear the streak on TARGET or KNOWN_OTHER. Pause/reset on leaving the app or inactivity. Exclude incomplete trees, geometry ties, modal transitions and pending author-only failures. |
| HealthMonitor.shouldAlert | Initial heuristic is five consecutive genuinely unrecognized samples spanning at least 10 s of target activity. A catalog parse failure can surface a configuration diagnostic immediately. A version change begins a fresh health streak. Log the tested profile and record successful generic fallback separately. Persist a visible degraded state until recognized evidence returns. |
| HealthNotifier.publish / recover | Use NotificationManager, a low-importance “Selector health” channel, stable notification ID per target and an immutable PendingIntent opening MainActivity. Subject identifies Instagram or YouTube and says selectors may be outdated. Use the last post time to limit repeat posts to once per package/version per 24 h. If notification permission/channel is unavailable, retain the dashboard notice. Clear an active notification on recovery. [Notification permission behavior](https://developer.android.com/develop/ui/views/notifications/notification-permission) |
| DebugActivity.armNextCapture(package) | From the app, arm one capture for the chosen platform, then let the tester switch to the target. Display armed/completed/expired status. Expire after 60 s, cancel on service disconnect, and consume only the first complete requested frame. If disconnected show enable-service instructions. |
| TreeDumper.writeSanitized(frame, result) | In debug only, write schema-v1 fixture JSON to app-private files/fixtures with generated filenames. Preserve geometry, role-bearing labels, selection and hierarchy. Replace identity/caption values consistently and redact unrelated text/description fields, including editable/password fields. If the redactor cannot establish which text to preserve, omit that text and mark the fixture for review. |
| DebugActivity.renderDiagnostics(summary) | Show service connection, version/profile, last result, reason codes, capture latency, nodes visited, truncation and coalescing counts, recent storage/overlay failure and capture filename. Use adb run-as for retrieval from a debuggable build. Limit logcat under ReelGuard to package, event type, timings and reason codes. |

**Maintainer workflow.** Capture the broken target and its closest ordinary look-alike on the same version. Review sanitization and expected outputs, add fixtures and implement a narrowly scoped profile or fallback. Replay previous profiles and confirm on-device. Unknown detection remains nonblocking while evidence is gathered. A changed app can still match a normal-screen rule incorrectly, so keep manual update checks alongside the heuristic.

**Acceptance.** Simulate 12 s of unknown frames with ongoing events in one package and expect one notice. Known YouTube home for the same duration stays healthy. Deny notification permission and verify the dashboard still explains the problem. Confirm successful recognition clears the active issue, cooldown survives restart, and debug capture of a user-selected screen yields a sanitized readable fixture. Inspect a release APK for absence of TreeDumper, debug Activity and capture action.
