# Content identity, whitelist and recent creators

**Owners.** Place CreatorKey and ContentIdentity in the Java core. WhitelistStore and its preferences adapter own the saved membership. The service calls these operations after item selection and before accounting or enforcement. Both the typed-entry UI and detector must use the same normalization.

| Operation | Contract |
|---|---|
| CreatorKey.parse(platform, rawHandle) | Trim, normalize Unicode to NFC, lowercase with Locale.ROOT and remove one optional leading @. Reject empty input, whitespace inside the handle, control characters, URLs, colon and a second @. For IG allow letters a–z, digits, period and underscore. For YouTube preserve Unicode letters/marks/digits and supported handle punctuation established by fixtures, including period, underscore, hyphen and middle dot. Reject display-name-only nodes at extraction. Store ig:khanacademy or yt:@3blue1brown. Return a validation result for the UI. |
| ContentIdentity.signature(platform, stableId, creator, caption) | Prefer an item ID verified stable across revisits. Otherwise use the canonical creator key plus the first 96 Unicode code points of a trimmed, NFC-normalized caption with whitespace collapsed. Require both inputs for this fallback. Encode platform, identity scheme and components with UTF-8 length prefixes and hash using SHA-256, lower-case hex. Surface is deliberately absent so a cross-surface revisit can dedupe. |
| WhitelistStore.list(), contains(key), add(key), remove(key) | Exact canonical membership. Return immutable snapshots. Repeated adds/removes are idempotent. Persist membership and publish a new revision on successful changes. Preserve the platform distinction for identical base handles. |
| rememberSeen(key), recent(limit) | On a resolved target observation, move the distinct key to the front of a persisted MRU list, capped at 20 across both platforms. Ignore unresolved handles. If already first, skip the write. Quick add uses the stored key intact. |
| eligibility(platform, key, membership) | Return EXEMPT for a match, ELIGIBLE for a known nonmatch, and PENDING for an unresolved author if any whitelist entry exists on that platform. With no entries for that platform, unresolved is ELIGIBLE. Re-evaluate after a capture or whitelist revision. |

**Identity stability.** Pick one extraction scheme per profile and surface based on discovery. If a stable-ID profile momentarily lacks its ID, leave the signature absent until it resolves. Choose a consistent collapsed caption role for the caption scheme. Suppress ambiguous edits where expanded text cannot be tied to a stable prefix. Two distinct reels with identical fallback inputs collide and may undercount. Capture this case in diagnostics and fixtures before changing the scheme.

**Late creator example.** A fresh IG reel renders its player before its author. With an IG whitelist, time and enforcement remain pending. If the next observation resolves to a member, start exempt accounting then. If it resolves to a nonmember, start eligible accounting then and immediately check the existing quota. Unverified pending time is discarded. If author remains unreadable, show an unresolved-author diagnostic and leave the reel usable. With only YouTube members, this IG observation follows the empty-IG-list rule.

**Acceptance.** Cover mixed case, optional @, duplicate entries, Unicode YouTube handles, invalid typed input, same base handle across platforms, creator shown only in suggested content, and 21 distinct recent entries. Verify a whitelist edit during a visit splits future accrual at confirmation and leaves committed history intact. Verify player controls changing do not change the signature.
