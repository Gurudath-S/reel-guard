# ReelGuardService and scheduling

**Role.** The Android AccessibilityService is the composition root for capture, classification, accounting, policy and enforcement. Android owns binding. Use one main Handler for callbacks, timers and window actions, one serial worker for live capture/classification, and the application repository executor for serialized usage and settings operations. Keep the pure engine on the repository executor. Carry immutable messages across boundaries. [AccessibilityService API](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService)

| Entry point | Required effects |
|---|---|
| onServiceConnected() | Invalidate any old generation, initialize handlers and collaborators, load selectors, package versions, settings, window, totals and recent counted history. Register settings/clock/screen listeners and publish CONNECTED. Coalesce incoming events while initialization finishes, then request one fresh capture. |
| onAccessibilityEvent(event) | Copy package, window ID, type and receive-time sample before returning. Accept only the three configured event types and two packages. Reject self/overlay events. Update the last target-event time. A window or package transition invalidates pending captures/actions. Only the focused active application may supply usage. |
| scheduleCapture(trigger) | Window-state or new-window event requests the earliest available capture. Batch content changes and scrolls on a 300 ms window measured from the first pending event. Bursts cannot indefinitely postpone that capture. Keep at most one in flight and one dirty follow-up. On a scroll invalidate pending action evidence immediately. |
| captureAndClassify(ticket) | Re-read active application window, root package and bounds. Check interactive/unlocked state. Active system dialogs, unsupported windows, foreign roots and missing or ambiguous roots suspend tracking. In split-screen inspect only the active target pane. During enforcement use the enforcer's owner check. Build the snapshot on the capture worker, release live objects there and route a plain result onward. |
| processObservation(result, stamp) | Check generation, monotonically increasing capture sequence and window ownership. Resolve settings/window/membership, remember a verified creator, and evaluate entry policy. Close/split prior usage as appropriate. For already-exhausted eligible entry, request block before opening a new visit. Otherwise apply counter step, commit due checkpoints, then evaluate policy on committed usage plus any verified unflushed delta exactly once. Flush a threshold crossing before dispatch. |
| armTimers(nextDue), onInactivity(ticket) | Schedule the earliest active confirmation for dwell, checkpoint, warning/block deadline or reset. Prioritize inactivity at last real target event + 3,000 ms. Timer captures do not refresh that clock. On expiry invalidate pending work, close at last confirmed sample, clear warnings/overlay views and stop polling. Fresh real events can reopen a session. |
| onSettingsChanged(revision), onClockChanged(), onScreenOff() | Reevaluate with a fresh capture after a material edit. Apply window change rules and re-arm elapsed-time deadlines from fresh clock samples. Screen off/lock cancels capture, accounting and overlay immediately. Resume only with verified foreground evidence. |
| onInterrupt(), onUnbind(), onDestroy() | Interrupt quiesces current feedback and session, permitting a later valid event while still bound. Unbind/destroy invalidate connection generation, unregister receivers/listeners, close/flush through the last confirmed sample, clear windows and publish disconnected status. Make teardown idempotent. |

## Coordination and races

Attach connection generation, target window, capture sequence and action revision to async results. Drop obsolete captures before advancing the engine. Serialize every accepted observation and settings edit. Post enforcement to the main thread only after its usage commit. Before Back, Home or attaching a block, validate the current owner and action revision again. If a navigation/content transition makes the item uncertain, request fresh classification. Ignore obsolete action requests even when the earlier, valid usage was durably counted.

Maintain the 3 s timer because the package filter can hide departures. A target can be quiet while a reel continues playing. The baseline intentionally stops accruing after the inactivity cutoff until new target activity arrives. An early null root or changed active app stops the session sooner. While idle there is no scanning loop. Keep debug metrics for capture latency, frame drops, nodes and coalesced events.

**Use cases and acceptance.** Generate content changes every 50 ms and confirm roughly one capture per 300 ms batch plus due confirmations, with no queue growth. Send a scroll then switch to DMs during a slow database write. The count already earned survives and the stale Back is discarded. Verify silent exit, sleep, screen lock, rotation, permission revocation and clean recreation. After process death resume from disk without inferring elapsed use.
