# OverlayEnforcer

**Dependencies and ownership.** Only the connected service's main thread operates WindowManager, LayoutInflater and performGlobalAction. Use TYPE_ACCESSIBILITY_OVERLAY. Maintain at most one warning or block view and one active enforcement episode. Keep the target package, window ID, verified bounds, generation and decision revision with it. [Accessibility overlay semantics](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#TYPE_ACCESSIBILITY_OVERLAY)

| Method | Behavior |
|---|---|
| apply(decision, owner) | Reject stale decisions. ALLOW removes a view belonging to that episode. WARN displays a brief banner when its warning key is due. BLOCK removes a warning and starts one block episode per confirmed entry. |
| showWarning(key, decision) | Inflate a nonfocusable, nontouchable banner inside target bounds for 2 s. Show the triggering metric, e.g. “8 of 10 reels used.” Mark delivered after successful attach and cancel scheduled removal if superseded. |
| beginBlock(owner, decision) | Obtain fresh owner validation. Stop accounting. Attempt GLOBAL_ACTION_BACK once, then attach the opaque touchable shield if the target is still current or awaiting the immediate navigation result. If the owner has already changed or a fresh capture shows a normal screen, release immediately. Further updates in the same episode must not issue another Back. |
| attachShield(bounds, message) | Cover the target app content, filling the app window on a full-screen phone. Use current window bounds in split-screen, top/start gravity and offsets adjusted to the overlay's coordinate origin, insets and layout direction. Consume touches within the shield. Keep system navigation available. Use a nonfocusable, touchable window and FLAG_NOT_TOUCH_MODAL for bounded panes. Provide an accessible Close app button and show reason and reset time. |
| verifyOwner(), onCloseApp(), dismiss(reason) | Check active underlying application and screen via the service, excluding ReelGuard's own overlay. A successful Back can land on a photo feed without changing window ID, so reclassify the actual surface. On Close app verify ownership, send GLOBAL_ACTION_HOME once and recheck. Remove callbacks, buttons and attached view idempotently. |

**Reconciliation.** Re-read the underlying target immediately after navigation, then at most every 300 ms while a shield is attached and the service session is active. Only keep the shield while a current eligible blocked surface is confirmed. Release on a normal screen, an unresolvable owner, foreign app, allowed creator, loss of focus, reset, inactivity, screen lock or disconnect. If Back fails and the target remains blocked, keep the shield with Close app available. If Home fails, keep a working Close app button for a deliberate retry. Never auto-loop either global action. If window attachment fails, clear local view state, publish a diagnostic and retry only on fresh eligible evidence.

**Device acceptance.** At count three the third reel is recorded before any Back. If Back lands in a normal feed the shield clears on verification. If Back leaves the target blocked, tapping the shield cannot scroll through to the video and Close app returns Home. Reenter an exhausted surface with a known nonmember and measure event-to-block latency against one capture/debounce cycle plus processing time (aim for under 500 ms on the test phone). Test whitelist grace, an unrelated foreground switch during Back, one-handed/system navigation, dark mode, rotation and interaction with the other split-screen pane. When pane coverage cannot be verified, release the overlay and record the geometry failure.
